# ITAMS Enterprise

IT Asset Management System for tracking company IT assets across their full lifecycle — registration, assignment, maintenance, warranty, licenses, and audits — with role-based dashboards for Administrators, IT Staff, and Managers.

Built with **Laravel 12**, **MySQL**, **Redis**, and **Tailwind CSS**.

## Features

- **Asset management** — register, edit, retire assets with categories, locations, brands, purchase info, and auto-generated QR codes
- **Assignments** — request/approve/reject/return workflow for asset handovers
- **Maintenance** — schedule preventive & repair maintenance with calendar and status tracking
- **Warranty tracking** — expiring & expired warranty alerts
- **License management** — software license inventory and usage tracking
- **Audits** — periodic asset audit records with verification workflow
- **Reports** — asset, maintenance, audit, and license reports with Excel/PDF export
- **Role-based dashboards** — ADMIN, IT STAFF, and MANAGER with KPIs and charts
- **Admin console** — user management, role/permission management, and app settings
- **Activity logging** — audit trail of key actions

## Requirements

- PHP 8.2+
- Composer
- MySQL 8+
- Redis
- Node.js 18+ & npm (for asset compilation)

## Installation

```bash
# 1. Install dependencies
composer install
npm install

# 2. Environment
cp .env.example .env
php artisan key:generate

# 3. Configure .env (database & redis credentials)
#    DB_CONNECTION=mysql, DB_DATABASE, DB_USERNAME, DB_PASSWORD
#    CACHE_STORE=redis, SESSION_DRIVER=redis, QUEUE_CONNECTION=redis

# 4. Database
php artisan migrate --seed

# 5. Serve
npm run build
php artisan serve
```

Queue worker is required for background jobs (e.g., email reminders):

```bash
php artisan queue:listen
```

## Roles

| Role | Scope |
| --- | --- |
| ADMIN | Full access — users, roles, settings, all modules |
| IT STAFF | Day-to-day asset, assignment, maintenance, and license operations |
| MANAGER | Read-focused dashboards, reports, and approval visibility |

Seed with `php artisan db:seed` to create default roles, permissions, and an administrator account.

## Deployment (Render free tier)

This repo ships with a [Dockerfile](Dockerfile) and a [render.yaml](render.yaml) blueprint that deploy the app on **Render's free plan** — a Docker-based web service (PHP 8.2 + Apache) backed by a free **PostgreSQL** database. No credit card is required.

> Free-tier limits: the web service sleeps after 15 min of inactivity (cold start ~1 min), the free Postgres database **expires 30 days after creation**, uploaded files are ephemeral (QR images are regenerated on demand), and SMTP ports are blocked (use the Resend HTTP API for email).

### Steps

1. Create a free account at https://render.com and connect your GitHub account.
2. Dashboard → **New → Blueprint** → select `Enterprise-IT-Asset-Management-System`.
   Render reads `render.yaml` and creates the Postgres database + web service automatically.
3. Wait for the first deploy to finish (build ~5 min).
4. In the **Environment** tab of the `itams` service, set:
   - `APP_URL` → your live URL (e.g. `https://itams.onrender.com`)
   - (optional) `RESEND_API_KEY` + set `MAIL_MAILER=resend` to send real reminder emails
5. Click **Manual Deploy → Deploy latest commit**.
6. Log in with the seeded admin account:
   - Email: `admin@itams.local`
   - Password: `password`

The first boot automatically runs `php artisan migrate --seed` (roles, permissions, admin user, demo data).

### Scheduled reminders (warranty/maintenance emails)

Render free does not include cron jobs, so the scheduler runs through an external free cron service (e.g. https://cron-job.org):

- Endpoint: `https://<your-app>.onrender.com/cron/<CRON_TOKEN>`
- Find `CRON_TOKEN` in the Render Environment tab (generated by the blueprint).
- Create a cron job hitting that URL **every 5 minutes** (or daily at 07:00 for just the reminder emails).
- The endpoint is protected by the token; keep it secret.

### Using a real database on Postgres

Migrations and seeders are database-agnostic, so no code changes are needed — Render injects the `DB_*` variables from the free Postgres instance. For local development the app defaults to MySQL/Redis; on Render the blueprint sets `CACHE_STORE=database`, `SESSION_DRIVER=database`, and `QUEUE_CONNECTION=sync` to avoid needing Redis or a background worker.
